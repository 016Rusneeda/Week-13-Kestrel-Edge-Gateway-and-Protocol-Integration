## 4. คำถามท้ายการทดลอง
1. เพราะเหตุใด SignalR จึงให้ประสบการณ์การใช้งาน (UX) บนหน้าเว็บที่ดีกว่าการใช้คำสั่ง JavaScript `setInterval()` เพื่อทำ HTTP GET Polling ซ้ำๆ ทุก 500 ms?

   **ตอบ** เพราะ SignalR ใช้เทคโนโลยี WebSockets เปิดการเชื่อมต่อแบบสองทางค้างไว้ เซิร์ฟเวอร์จึงสามารถ "พุช (Push)" ข้อมูลไปแสดงบนเว็บได้ทันทีแบบเรียลไทม์ ช่วยลดความหน่วงและลดภาระเครือข่ายเพราะไม่ต้องเสียเวลาสร้าง HTTP Request ใหม่ซ้ำๆ เหมือนการทำ Polling
   
2. การคำนวณและแสดงผล Protocol Convergence Metrics ส่งผลดีต่อการตรวจสอบสุขภาพของระบบเครือข่ายไอโอทีในระดับโรงงานอย่างไร?

   **ตอบ** ช่วยให้ผู้ดูแลระบบเห็นภาพรวมสุขภาพเครือข่าย และใช้ชี้จุดเกิดปัญหาได้รวดเร็ว เช่น หากยอดฝั่ง Serial วิ่งปกติแต่ยอด MQTT หรือ SignalR ไม่ขยับ ก็สามารถระบุได้ทันทีว่าปัญหาอยู่ที่ซอฟต์แวร์ Gateway ไม่ใช่ที่ตัวฮาร์ดแวร์เซนเซอร์พัง
